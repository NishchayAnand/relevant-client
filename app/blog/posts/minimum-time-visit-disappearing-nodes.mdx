There is an undirected graph of `n` nodes. You are given a `2D` array edges, where 
`edges[i] = [ui, vi, lengthi]` describes an edge between node `ui` and node `vi` with 
a traversal time of `lengthi` units.

Additionally, you are given an array `disappear`, where `disappear[i]` denotes the time 
when the node `i` disappears from the graph and you won't be able to visit it.

Return the array `answer`, with `answer[i]` denoting the minimum units of time required to 
reach node `i` from node `0`. If node `i` is unreachable from node `0` then `answer[i]` is `-1`.

#### Example: Emergency Fire Response

Imagine a fire station dispatching emergency response teams to different houses across a city. 
Roads connecting the locations have different travel times, and some houses may become completely 
engulfed in flames after a certain time, making them inaccessible.

Determine the earliest time an emergency team can reach each house, ensuring it arrives before that 
house becomes inaccessible.

### Basic Intuition

1. We need to find the minimum time required to reach every node connected to the source node, 
provided it is within the accepted threshold. 

2. An edge list is not an efficient representation for this problem, as it requires scanning the 
entire list to identify the neighbours of a particular node. We can convert the edge list into 
an adjacency list, which allows us to directly access the neighbours of a node.

3. An improvement in one node's shortest path can lead to improvements in other nodes' shortest distances.
Therefore, whenever we discover a shorter path to a node, we need to explore its neighbours again using the 
updated distance.

---

### Naive Approach: Shortest Path Faster Algorithm

We start from the source node and explore its neighbours. Whenever we find a shorter path 
to a node, we add it to a **<span className="bg-emerald-300 rounded p-0.5">queue</span>** so that we can explore its neighbours using the updated distances.

#### Algorithm

```java
1. Covert the input edge list into an adjacency list. Since the graph is undirected, 
   add each edge in both directions, so that each endpoint (node) is represented as 
   a neighbour of the other.

2. Create an "answer" array of size "n", initializing the minimum travel time for each 
   node to Infinity.
3. Set the minimum time of the source node to 0 and add it to the queue.

4. Continue processing until the queue becomes empty.
    5. Remove the oldest node from the queue and retrieve its current minimum travel time.
    6. Iterate over all outgoing neigbours of the current node along with their corresponding
       edge weights.
        7. For each neighbour, calculate the minimum travel time required to reach it through the 
           current node: "newTime = answer[currentNode] + edgeWeight". 
        8. If "newTime" is smaller than the existing minimum travel time of the neighbour and denotes
           not exceed the threshold, update its minimum travel time add the neighbour to the queue.

8. Replace the minimum travel time for all unreachable nodes from Infinity to -1.
9. Return the "answer" array.
```
