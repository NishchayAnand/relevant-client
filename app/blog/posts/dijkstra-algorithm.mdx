Dijkstra's Algorithm is a graph traversal algorithm used to **find the shortest 
path from a source node to all other nodes in a weighted graph, provided all 
edge weights are non-negative**.

#### Example: Travelling Between Countries

Imagine you are travelling between different countries and want to find the minimum 
time required to travel from India to every other country.

---

### Key Observations

1. Out of all the nodes whose shortest path are not yet confirmed, we can pick the 
node with the smallest known distance from the source. Any alternative path to 
this node must pass through another unprocessed node. Since all edge weights 
are non-negative, that path cannot produce a shorter distance than the one we 
have already found.

2. Once we know the shortest path of a node from the source, we can explore its 
neighbours and attempt to improve their shortest known distances.

---

### Algorithm

The algorithm uses a **<span className='bg-indigo-200 p-0.5 rounded'>greedy approach</span>** 
combined with a **<span className='bg-indigo-200 p-0.5 rounded'>min-priority queue</span>** 
to always process the node with the smallest known distance from the source. By repeatedly 
exploring its neighbours and relaxing edges, we gradually determine the shortest paths 
to all reachable nodes.

Let's understand the algorithm through the following questions.

##### **<span className='text-emerald-500'>Q1. How do we start?</span>**

We start from the source node with an initial distance of `0`. Initialize the distance of 
all other nodes to `infinity`.

![algorithm-1](/dijkstra-algorithm/algorithm-1.png)

##### **<span className='text-emerald-500'>Q2. What do we do after initializing the distances?</span>**

We explore all the neighbours of the source node and update their shortest known distances 
based on the corresponding edge weights.

![algorithm-2](/dijkstra-algorithm/algorithm-2.png)

##### **<span className='text-emerald-500'>Q3. How do we store the unprocessed nodes?</span>**

We use a **min-priority queue** to store the discovered nodes along with their shortest 
known distances from the source.

![algorithm-3](/dijkstra-algorithm/algorithm-3.png)

##### **<span className='text-emerald-500'>Q4. How do we decide which node to process next?</span>**

We extract the node with the smallest known distance from the priority queue. This ensures 
that we always process the closest unprocessed node first.

![algorithm-4](/dijkstra-algorithm/algorithm-4.png)

##### **<span className='text-emerald-500'>Q5. What happens when we process a node?</span>**

We explore all its neighbours and attempt to improve their shortest known distances by 
relaxing the edges.

For every neighbour, we calculate: `newDistance = dist[currentNode] + edgeWeight`.
If the newly calculated distance is smaller than the existing distance, we update it and 
insert the updated entry into the priority queue.

![algorithm-5](/dijkstra-algorithm/algorithm-5.png)

##### **<span className='text-emerald-500'>Q6. How do we continue the process?</span>**

We repeat the same process:

```
1. Extract the node with the smallest known distance.
2. Explore its neighbours.
3. Relax the edges and update distances if a shorter path is found.
4. Insert the updated entries into the priority queue.
```

We continue until the priority queue becomes empty.

##### **<span className='text-emerald-500'>Q7. What is the final result?</span>**

At the end, the distance array contains the shortest distance from the source node to 
every reachable node.

![algorithm-6](/dijkstra-algorithm/algorithm-6.png)

<Note>
**Nodes that remain unreachable retain an infinite distance.**
</Note>

### Implementation

Most DSA problems represent a graph using an array of edges where each entry represents: 
`{source, destination, weight}`.

An **Edge List** is a convenient way to provide the graph as input because we only need to 
specify the existing connections. However, it does not provide an efficient way to 
explore the neighbours of a particular node.

To find the neighbours of a node, we would have to iterate over the entire **Edge List** and 
identify all edges connected to that node. Since Dijkstra frequently explores the 
neighbours of the currently extracted node, repeatedly scanning the entire **Edge List**
introduces unnecessary overhead.

### Time Complexity

Let:

(V) = Number of vertices.

(E) = Number of edges.

Using an adjacency list and a binary min-heap:

Building the adjacency list takes (O(V + E)).

Edge relaxation and priority queue insertion take (O(\log V)) per successful relaxation.

Extracting nodes from the priority queue takes (O(\log V)) per extraction.

Therefore, the overall time complexity is:

```
\boxed{O((V+E)\log V)}
```

---

### Space Complexity

We use:

Adjacency list: (O(V+E)).

Distance array: (O(V)).

Priority queue: (O(E)) in the lazy implementation.

Therefore, the overall space complexity is:

```
\boxed{O(V+E)}
```
